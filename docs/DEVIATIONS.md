## D-001 · ยุบบทบาทครูเข้ากับ admin

**สถานะ:** อนุมัติแล้ว · 18 ส.ค. 2569

**Blueprint ที่เกี่ยวข้อง:** #75 Teacher Dashboard · #78 Teacher Preview Mode ·
#110 Teacher Role · #113 ครูทดลองเป็นนักเรียน · #196 Teacher Intervention Engine ·
CLAUDE.md → Testing (Teacher View, Teacher Preview)

**Blueprint กำหนดว่า:** ต้องมีบทบาท Teacher แยกจาก Admin
พร้อมแดชบอร์ดครู โหมดทดลองเป็นนักเรียน และสิทธิ์จัดการเนื้อหา

**โปรเจกต์นี้ทำ:** ไม่มี role `teacher` ในระบบ
ครูผู้สอนใช้บัญชี `admin` เพียงบัญชีเดียว

**เหตุผล:** โรงเรียนบ้านเขาธรรมบทมีครูผู้สอนวิชานี้คนเดียว
คือ นายกิตติคุณ จันทะคุณ ซึ่งเป็นทั้งครูและผู้ดูแลระบบ
การแยกสองบทบาทสร้างบัญชีซ้ำซ้อนโดยไม่มีผู้ใช้จริงรองรับ

**สิ่งที่ถูกลบออกใน commit `4191c49`:**

- `setupTeacherAccount()`
- `getTeacherDashboard()`
- `setDownloadFileIds()`
- `validateDriveFileId_()` และ `upsertSetting_()` (ตัวช่วยที่เหลือไว้ใช้คนเดียว)

**ผลกระทบที่ยอมรับ:**

- ครูไม่มีสิทธิ์จัดการเนื้อหาแยกจาก admin (#82, #126) ซึ่งยังไม่มีทั้งคู่

**แก้ไขแล้ว 18 ส.ค. 2569:** เดิมบันทึกไว้ว่ายังไม่มี Teacher Preview Mode
ตอนนี้ทำแล้วผ่าน `startTeacherPreview()` ซึ่งใช้ Synthetic Session
เก็บความก้าวหน้าไว้ใน CacheService ไม่แตะชีตของนักเรียนจริง ตรงตาม #113
มีทั้งโหมดเดินตามลำดับและโหมดข้ามขั้นตาม #79 และล้างข้อมูลทดลองได้ตาม #80

จึงเหลือเพียงเรื่อง role ที่ยังยุบรวมกับ admin ตามที่ตัดสินใจไว้

**กู้คืนได้:** `git show 4191c49 -- Code.gs`

## D-002 · นักเรียนเปลี่ยนรหัสผ่านเองไม่ได้

**สถานะ:** อนุมัติแล้ว · 18 ส.ค. 2569

**Blueprint ที่เกี่ยวข้อง:** #109 Security · #184 Privacy by Design

**โปรเจกต์นี้ทำ:** ลบหน้าจอตั้งรหัสผ่านใหม่และฟังก์ชัน `changePassword()` ออกทั้งหมด
ครูเป็นผู้กำหนดรหัสให้ทุกคนผ่าน `resetStudentPasswords()` ใน `Maintenance.gs`
รหัสนักเรียนยังใช้เกณฑ์ผ่อนปรน 4 ตัวอักษรขึ้นไปตาม D-002 แต่ค่าปัจจุบันต้องเก็บเฉพาะในระบบยืนยันตัวตนและห้ามบันทึกในไฟล์ที่ Git ติดตาม

**เหตุการณ์ความลับ 29 ส.ค. 2569:** ลบค่าที่เคยบันทึกไว้ในเอกสารนี้แล้ว และถือว่าค่าเดิมถูกเปิดเผย Production ได้หมุนเวียน credential ผ่าน hardened Admin path บน v38 ครบ 7 บัญชี ยกเลิก session เดิม 7 บัญชี และตรวจ fresh login พร้อมข้อมูลการเรียนคงอยู่สำเร็จแล้ว จึงปิด Production credential/session blocker ได้ ส่วนหลักฐานเดิมที่ยังอยู่ใน Git HEAD/history เป็นความเสี่ยงฝั่ง repository ที่ต้องจัดการแยกต่างหากเมื่อได้รับอนุมัติ
**แผนแก้ไขและหลักฐานปิดเหตุการณ์:** ดู [CREDENTIAL_ROTATION_PLAN.md](CREDENTIAL_ROTATION_PLAN.md) และ `FINAL_SECURITY_GOLD_REPORT_20260829.md` ห้ามส่งค่ารหัสผ่านแชตหรือบันทึกลงเอกสาร

**เหตุผล:** นักเรียน ม.1 จำนวน 7 คนเริ่มจากศูนย์
ครูต้องการลดขั้นตอนที่ทำให้เด็กเข้าระบบไม่ได้ในคาบเรียน
และครูอยู่กับนักเรียนตลอดคาบจึงควบคุมการเข้าถึงได้โดยตรง

**ความเสี่ยงที่ยอมรับ:** เว็บแอปตั้งค่า `access: ANYONE_ANONYMOUS`
ผู้ที่ได้ URL สามารถลองเดารหัสได้ แต่เห็นได้เฉพาะความก้าวหน้าของนักเรียนคนนั้น
เข้าหน้า admin ไม่ได้ และมีการล็อกเมื่อกรอกผิดเกิน 5 ครั้งใน 10 นาที

**ข้อควรระวัง:** ห้ามเผยแพร่ URL เว็บแอปในที่สาธารณะ

**บัญชี admin ยังใช้เกณฑ์เข้ม** 8 ตัวอักษรขึ้นไป มีทั้งตัวอักษรและตัวเลข

## D-003 · ยังไม่มีมาตรฐานและตัวชี้วัดในระบบ

**สถานะ:** ค้าง รอข้อมูลจากครู

**Blueprint ที่เกี่ยวข้อง:** #3 ข้อมูลพื้นฐานของรายวิชา · #119 Alignment Matrix ·
#177 Curriculum Traceability · #179 Objective ID

**สถานะจริง:** ตรวจ `lesson-plan.docx` ทั้งฉบับแล้ว
**ไม่พบข้อมูลในแหล่งที่ได้รับ** — ไม่มีรหัสมาตรฐาน ไม่มีรหัสตัวชี้วัด
ไม่มีการอ้างอิงหลักสูตรแกนกลาง

แผนการสอนมีเพียงจุดประสงค์การเรียนรู้แบบ K–P–A ซึ่งใช้แทนตัวชี้วัดไม่ได้

**การปฏิบัติ:** ตาม Blueprint #3 ห้าม AI แต่งมาตรฐาน ตัวชี้วัด
หรือรหัสหลักสูตรขึ้นเอง จึงยังไม่ใส่ข้อมูลส่วนนี้ลงระบบ

**สิ่งที่ต้องการจากครู:** รหัสตัวชี้วัดจริงจากหลักสูตรแกนกลาง
กลุ่มสาระการเรียนรู้วิทยาศาสตร์และเทคโนโลยี (วิทยาการคำนวณ) ชั้น ม.1
เพื่อทำ Alignment Matrix และ Curriculum Coverage Dashboard ต่อไป

## D-004 · ปิดการสำรองข้อมูลอัตโนมัติรายคืน

**สถานะ:** ปิดแล้ว 25 ก.ย. 2569 · ยืนยันแล้วว่าหน้า Triggers ขึ้น "กำลังแสดง 0 ทริกเกอร์"

**Blueprint ที่เกี่ยวข้อง:** #205 Backup · #206 Restore Test · #229 Production Readiness (หมวด Data)

**สิ่งที่เปลี่ยน:** ลบ trigger ที่เรียก `runScheduledBackup()` ออกจากโปรเจกต์
Apps Script ของ Production ระบบจึงไม่สำเนาสเปรดชีตไปเก็บใน Drive ทุกคืนอีกต่อไป

ลบผ่านหน้า Apps Script editor → Triggers เท่านั้น เพราะ trigger ไม่มีใน Apps Script API
และ clasp สั่งลบไม่ได้ · ครั้งนี้ agent ลบให้โดยควบคุม Chrome ที่ครูล็อกอินไว้
ตามคำสั่งของครู แล้วรีโหลดหน้ายืนยันว่าเหลือ 0 ทริกเกอร์

ก่อนลบ trigger ตัวนี้เรียกใช้ล่าสุดเมื่อ 25 ก.ย. 2569 01:01:13 อัตราข้อผิดพลาด 0%

**โค้ดไม่ได้ถูกแก้:** `runScheduledBackup()`, `createBackup_()`, `installDailyBackup_()`
และปุ่มเปิดการสำรองในหน้าครูยังอยู่ครบและทำงานได้เหมือนเดิม
การปิดครั้งนี้เป็นการเปลี่ยนค่าการตั้งค่าใน Apps Script ไม่ใช่การถอดฟีเจอร์ออกจากระบบ

**ความเสี่ยงที่ยอมรับ:** ข้อมูลการเรียนของนักเรียนเหลือสำเนาเดียวคือสเปรดชีตตัวจริง
ถ้าไฟล์ถูกลบถาวรหรือเสียหายทั้งไฟล์ จะไม่มีสำเนาให้กู้
สิ่งที่ยังพอช่วยได้คือ Version history ของ Google Sheets ซึ่งกู้ได้เฉพาะกรณีแก้ข้อมูลผิด
แต่ช่วยไม่ได้ถ้าไฟล์หายทั้งไฟล์

**สิ่งที่ยังอยู่:** ไฟล์สำรองเดิม 5 ไฟล์ (21–25 ก.ย. 2569) ยังอยู่ในโฟลเดอร์สำรอง
ไม่ได้ถูกลบไปพร้อมกับการปิด trigger

**วิธีเปิดกลับ:** ปุ่มเปิดการสำรองอัตโนมัติในหน้าครู ซึ่งเรียก `enableDailyBackup(token)`
ผ่าน role guard ระบบจะสร้าง trigger ใหม่และสำรองให้ทันทีหนึ่งครั้ง
ไม่ต้องแก้โค้ดและไม่ต้อง deploy ใหม่

**หมายเหตุสำหรับเซสชันถัดไป:** ถ้าตรวจระบบแล้วพบว่าไม่มีการสำรองรายคืน
**นี่คือสิ่งที่ครูตั้งใจ ไม่ใช่ความผิดปกติ** ห้ามเปิดกลับเองโดยไม่ถาม
และห้ามรายงานว่าเป็นบั๊กหรือ regression
